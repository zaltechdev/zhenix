# Aksa three-minute demo walkthrough

## Prepare before presenting

- Open [https://aksawork.web.id](https://aksawork.web.id) in desktop Chrome.
- Sign in before screen sharing and leave the browser on **Home**.
- Allow camera and microphone access. Start head control before the timer if model loading is slow.
- Keep the sidebar expanded and browser zoom near 90 percent.
- Close other camera applications, notifications, and unrelated tabs.
- Test these spoken commands once: `Open document` and `Open Gmail`.

## Timed script

| Time | Click or action | Say this |
| --- | --- | --- |
| 0:00-0:20 | Start on **Home**. Point briefly at the command box and Google Workspace shortcuts. | “This is Aksa, a web workspace for people who find mouse-heavy digital work difficult or painful. Aksa combines head control, voice commands, and AI-assisted work in one accessible interface.” |
| 0:20-0:45 | Click **Controls**. Show **Head control on** and move your head slightly so the Aksa pointer moves. Do not recalibrate during the demo. | “The pointer follows head movement, while dwell or a facial gesture can select a target. All camera processing stays inside the browser. Frames are never uploaded, and keyboard and mouse remain available.” |
| 0:45-1:05 | Click **Home**, then click **Live Voice**. Clearly say: **“Open document.”** | “Live Voice is command mode, not ordinary dictation. A finalized utterance is interpreted and executed immediately.” |
| 1:05-1:25 | Wait for **Docs** to open. Without clicking Live Voice again, say: **“Open Gmail.”** | “The same listening session remains active, so the user can issue another command without restarting the microphone. Duplicate browser callbacks are ignored.” |
| 1:25-1:45 | Click **Stop voice commands**. In the sidebar, click **Sheets**, **Slides**, then **Drive**, pausing briefly on each. | “Aksa brings familiar Google work surfaces into one consistent flow. The current competition build uses these screens to demonstrate the intended cross-app experience.” |
| 1:45-2:10 | Return to **Home**. Click **Dictate**, say **“Summarize my assignment”**, then stop dictation. Do not press Send. | “Dictation behaves differently: it only fills editable text. The user can review or correct what Aksa heard before sending anything.” |
| 2:10-2:35 | Click **Accessibility**. Point at reduced motion and keyboard or mouse fallback. Then click **Controls** and show voice language and mode choices. | “Accessibility is configurable, not forced. Users can adjust motion, pointer behavior, selection method, language, and voice mode while preserving standard input fallbacks.” |
| 2:35-2:50 | Click **History**, then **Activity**. | “History presents user-facing outcomes, while Activity exposes the steps Aksa performed. This keeps automated work visible without exposing private model reasoning.” |
| 2:50-3:00 | Return to **Home** and leave the command box visible. | “Aksa reduces precise pointing and repeated navigation while keeping the user in control. One deployed web app supports head movement, speech, typing, and mouse input.” |

## Recovery lines

### Microphone fails

Type `Open document`, click **Send command**, and say:

“Voice is optional. The same command works through typing, so microphone failure never blocks the task.”

### Head control fails

Continue with the mouse and say:

“Aksa detected that head control is unavailable and preserved the keyboard-and-mouse fallback by design.”

### A voice command is misheard

Click **Stop voice commands**, correct the text, then click **Send command**. Say:

“Aksa keeps the transcript visible and editable, so the user can recover without losing context.”

### Navigation stalls

Use the matching sidebar item and say:

“Every voice destination also has a visible navigation path, preserving input parity.”

## Avoid these claims

- Say **head control**, never eye tracking.
- Call the Google screens **competition concept previews** unless live Google data is visibly confirmed.
- Do not claim autonomous edits, sending, or undo unless demonstrated successfully during that run.
- Do not say camera frames reach the server. They stay in the browser.
